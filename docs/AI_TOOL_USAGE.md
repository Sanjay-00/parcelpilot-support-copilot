# AI Tool Usage

Claude Code (Anthropic's CLI agent) was the AI coding assistant used throughout this project. It was used as a hands-on collaborator across the whole lifecycle, not just for autocomplete:

- **Design before code.** Requirements were brainstormed into a written design spec (`docs/superpowers/specs/2026-08-21-parcelpilot-copilot-design.md`) and a step-by-step implementation plan (`docs/superpowers/plans/2026-08-21-parcelpilot-copilot-implementation.md`) before any application code was written, so architectural decisions (bounded classification vs. open-ended tool-calling, deterministic resolvers vs. model-computed answers, source-precedence rules) were made deliberately up front rather than discovered mid-implementation.
- **Implementation with review checkpoints.** Each unit of the plan was implemented, then code-reviewed (the `.superpowers/sdd/*/review-*.diff` files in this repo are the reviewer's diff-level feedback at each step) before moving to the next, catching real issues along the way -- e.g. an information-disclosure bug where `get_order`/`get_ticket` returned different error text for "belongs to another account" versus "doesn't exist," which would have let someone probe for another customer's record IDs.
- **Test-driven throughout.** Deterministic resolvers, authorization logic, and severity mapping were written test-first; the 113+ test suite (unit, integration, and a live-model generalization eval) was built incrementally alongside the code it covers, not bolted on afterward.
- **Self-directed generalization testing.** After the minimum requirements were met, Claude Code was directed to specifically hunt for overfitting to the assessment brief's own two example questions -- this produced a dedicated 29-question live-model evaluation suite (`tests/test_generalization_eval.py`) using data-pack records the brief never mentions, which found and led to fixing two real gaps: a missing general-purpose document-retrieval route, and a proactive issue-detection feature hardcoded to the two known issues in the sample data.
- **This robustness pass.** The LLM-based `general_inquiry` chunk-selection retrieval (`app/agent.py::_select_chunks_llm`, replacing pure keyword-overlap ranking as the primary path) was designed and implemented in a follow-up session with Claude Code, specifically to close a paraphrase-matching gap identified during a self-audit of the submission before finalizing it.

All architectural and product decisions, including where to disagree with or simplify a suggestion, were reviewed and made by the author; Claude Code was not left to make unreviewed design choices.
